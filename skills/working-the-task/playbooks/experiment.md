# Experiment

A throwaway instrument to settle one decision by observation instead of
argument. The real change, if any, is a later task.

1. Write down the decision it settles: which design, which behavior,
   whether a number moves. No decision, no experiment.
2. Build the smallest thing that exercises it, in a scratch folder
   outside the product's source (`/tmp/<name>` or a clearly named
   folder that is not committed). No tests, no abstractions.
3. When comparing alternatives, run each the same way and label them.
4. Observe the thing being decided: print the output, log the timing,
   take the screenshot. The observation is the result.
5. Time-box it. If it does not settle the question in that time, report
   what it showed and what would settle it.

Report: the variants, what you observed for each (with the commands),
the tradeoffs, your recommendation, and the scratch path. Say plainly
that the code is throwaway.
